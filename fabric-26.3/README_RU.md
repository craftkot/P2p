# OpenTogether Direct 0.12.0-alpha — Fabric Minecraft 26.3 (эксперимент)

Независимая версия без e4mc. **В JAR нет ни e4mc, ни собственного интернет-ретранслятора.**
Остаются меню друзей, кнопка входа, диагностические метрики и текстовые отчёты.
Изменения Forge 1.20.1 (в частности adaptive zlib и настройки сжатия)
не переносятся автоматически в Fabric 26.3: это отдельная кодовая база.

## Как соединить два ПК в LAN

1. На хосте зайди в одиночный мир → Esc → OpenTogether → **Открыть свой мир по LAN**.
2. В штатном меню Minecraft опубликуй мир. Вернись в OpenTogether и нажми **Скопировать приглашение**.
3. Поле содержит предлагаемый локальный IPv4 и фактический порт опубликованного Minecraft-сервера. Если у ПК несколько сетевых интерфейсов, проверь адрес вручную.
4. **Скопировать OT1-код**. Он помещается в буфер обмена.
5. У друга: OpenTogether → **Подключиться к другу** → **Вставить код** → **Подключиться**.
   Подойдёт также обычный адрес `host:port` вместо OT1-кода.

**OT1-код не является паролем.** В него закодирован только TCP-адрес и порт.
Тот, у кого есть код, узнает IP и порт, которые ты ввёл при создании кода.
Не публикуй код, если не собираешься раскрывать этот адрес.

## Интернет без e4mc

Точно тот же механизм работает через Интернет **только если TCP-порт хоста доступен** извне:
например, у хоста публичный IPv4 с настроенным пробросом порта, доступный IPv6 через
совместимый механизм (пока не поддерживается в формате OT1) или другая сеть с
маршрутизируемым адресом. Сейчас OT1 поддерживает IPv4 или DNS-имя, а не IPv6.

Порядок действий для публичного IPv4:
- Опубликуй LAN-мир, узнай фактический TCP-порт.
- Обеспечь доступность этого TCP-порта извне через настройки маршрутизатора
  и брандмауэр. При CGNAT одного проброса портов в домашнем роутере недостаточно.
- В поле приглашения замени локальный IP публичным IP или DNS-именем,
  **оставив фактический порт Minecraft**. Скопируй OT1-код и передай другу.
- Отключай публикацию LAN после игры; открытый игровой порт доступен не только друзьям.
  Не отключай брандмауэр целиком.

Только **короткий код комнаты без сетевого адреса** не решает обнаружение хоста:
для этого необходим хотя бы signaling/каталог узлов и механизм обхода NAT.
Исследуемый вариант: WebRTC/ICE или свой UDP-транспорт с TCP-мостом; если
прямой канал не открывается — собственный TURN/relay как резерв.
В этой сборке автоматических ICE, UPnP, TURN и NAT traversal **ещё нет**.

## Диагностика

Esc → OpenTogether → Диагностика: события клиентской загрузки чанков за 10 с,
кеш, дальность прорисовки, пинг гостя / тик хоста и копируемый отчёт.
События загрузки чанков **не являются измерением пропускной способности**.
Ноль событий при стоянии на месте нормален.

## Сборка и проверки

Нужны JDK 25, Gradle 9.8 и Fabric Loader 0.20.1. Выполни из `fabric-26.3`:
`gradle --no-daemon clean build`.

В GitHub Actions проверяются компиляция, JUnit-тесты OT1,
отсутствие e4mc внутри JAR и запуск графического Minecraft-клиента.
**CI-компиляция не заменяет реальный P2P/LAN-тест на двух компьютерах.**
