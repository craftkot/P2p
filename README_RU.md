# OpenTogether 0.8.0-alpha — один файл, автоматические приглашения и диагностика чанков

Minecraft Java 1.20.1, Forge 47.x, JDK 17. **Один файл** `opentogether-forge-1.20.1-0.8.0-alpha-all.jar`. e4mc 6.2.3 уже упакован внутри; отдельно его устанавливать нельзя и не нужно.

## Как пригласить
1. Удали старые версии OpenTogether и отдельный e4mc, оставив в `mods` только новый единый JAR.
2. Открой одиночный мир и нажми Esc → **Пригласить друга**.
3. Если мир ещё не опубликован, нажми **Открыть мир для друзей** и подтверди открытие LAN в стандартном окне Minecraft.
4. Когда встроенный e4mc присвоит временный домен, OpenTogether распознает его системное сообщение и **скопирует адрес в буфер обмена автоматически**. Вставь его другу в сообщение.
5. Если мир уже открыт, кнопка **Скопировать приглашение** позволит получить тот же адрес в один клик.

## Как подключиться
Друг вводит полученный адрес в **Подключиться к другу** → **Вставить приглашение** → **Подключиться**. e4mc нужен только хозяину мира и встроен в единственный файл OpenTogether. У друга должна быть совместимая версия Minecraft и одинаковые игровые моды, если они используются.

## Чего пока нет
- Автоматическая отправка приглашений по нику/список друзей: для этого нужна авторизованная система друзей, которой в моде пока нет.
- Собственный независимый P2P: используется внешний сетевой протокол и публичные ретрансляторы e4mc, доступность которых не гарантируется.
- Проверка успешного подключения двух реальных игроков и задержки через интернет: нужна отдельная проверка.

## Техническая часть
OpenTogether перехватывает только локальное **системное сообщение e4mc** с ключом `text.e4mc_minecraft.domainAssigned`. Другие сообщения игроков не сохраняются. Домен проходит проверку на окончание `.e4mc.link`; копирование активируется только явным открытием меню приглашения. Буфер обмена и кеш приглашения ограничены текущим миром.

Сборка выполняется GitHub Actions, проверяется наличие настоящей Forge Mixin reference map и вложенного e4mc. Логи — `logs/latest.log`.

e4mc: https://github.com/vgskye/e4mc-minecraft-architectury — MIT, автор Skye. Оригинальная лицензия находится внутри JAR. Драйвер туннеля остаётся e4mc, а OpenTogether обеспечивает интерфейс и интеграцию.


## Диагностика слабой загрузки чанков у друзей (v0.7)

- Открой свой мир и попроси друга подключиться, после чего нажми **Esc → Диагностика чанков**.
- В меню показаны число чанков в кеше клиента и количество новых событий загрузки за последние 10 секунд. Оба показателя важны во время движения по **уже созданной** местности. При неподвижном игроке число новых загрузок может быть нулём — это нормально.
- На стороне хозяина видны серверные расстояния отправки/симуляции и среднее время тика (цель для стабильных 20 TPS: **менее 50 мс**). На стороне гостя — задержка, если доступна через Minecraft.
- Нажми **Скопировать показатели** на обоих компьютерах и сравни. Этот мод **не собирает IP-адреса или UUID** в отчёт и ничего не отправляет в интернет для диагностики.
- Если у друга видны всего 1–2 чанка, а у хоста нормальные 8–12 и тики стабильны, проверяем сеть, публичный ретранслятор e4mc, скорость отдачи у хоста и потерю пакетов. Сама загрузка чанков может задерживаться из-за перегруженных общедоступных ретрансляторов.
- Если сервер выставил маленькую дальность отправки, увеличь дальность прорисовки у хозяина умеренно, например до **8–10**, а дальность симуляции для слабого ПК попробуй уменьшить до **4–6**. Нельзя гарантировать улучшение от увеличения расстояния: оно увеличивает объём данных.
- Новых вмешательств в отправку чанков и сетевые пакеты в 0.7 **нет**: сначала нужно объективно измерить, где задержка. Эти метрики сами по себе не доказывают причину низкой видимости.

О проблемах медленной загрузки именно через e4mc также сообщали его пользователи: https://github.com/vgskye/e4mc-minecraft-architectury/issues/47

## Оптимизация передачи чанков (версия 0.8)

При публикации одиночного мира OpenTogether теперь может включать стандартное Minecraft zlib-сжатие во время входа удалённых игроков. Это снижает объём передаваемых байтов, если данные хорошо сжимаются, но добавляет нагрузку на CPU. Реальное ускорение пока не измерено.

- Настройка автоматически появляется в config/opentogether-network.properties.
- Значение compressionThreshold=256 включает сжатие пакетов от 256 байт.
- Для менее мощного CPU можно попробовать 1024 или 4096. Для полного отключения нашего изменения: compressionThreshold=-1.
- Изменения вступают в силу после перезапуска Minecraft и нового подключения гостей. Живые TCP-соединения мод не перенастраивает.
- Применяется только к открытому одиночному миру, не к выделенному серверу.
- Если оба игрока используют OpenTogether, e4mc может установить прямое Dialtone/P2P-соединение; при неудаче остаётся ретранслятор. Для гарантированной совместимости адрес приглашения не меняется.
- Для сравнения используйте одну и ту же исследованную местность и отчёты «Диагностика чанков» при 256 и -1. Сжатие не исправляет перегрузку публичного ретранслятора или высокий пинг.
